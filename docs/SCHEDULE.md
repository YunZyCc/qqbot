# 她的一天

每天生成一份日程，聊天时她知道自己此刻在做什么，说说和签名也从这里取材。

## 为什么要有这个

以前问她「在干嘛」，答案永远是「等你说话呢」——因为她确实没有任何别的事可做。

有了日程之后：

```
你：在干嘛
她：在阳台上翻那本没看完的书，翻到一半有点走神
```

## 三层结构

| 层 | 存哪 | 干什么 |
|---|---|---|
| **日程** | `daily_plans` 表，按天一行 | 今天打算做什么 |
| **日记** | `diaries` 表，按人分开 | 今天实际发生了什么，**会读日程** |
| **回忆** | `embeddings` 表，`ref_type='diary'` | 按语义找回以前写过什么 |

日程是「计划」，日记是「事实」，向量是「记得住」。

## 生成

**不再定时生成**。两个触发点：

1. **每天第一次聊天时**（回复发出去之后异步生成，不拖慢第一条）
2. **她调用 `plan_lookup` 工具时**——你问「明天干嘛」，她现生成明天的

素材：

```
她的人设
+ 昨天日记的心情词
+ 最近 3 天的日程（避免重复）
+ 最近和主人聊的摘要（给个由头）
```

约束写死在 prompt 里：

```
- 3 到 6 个时段，从早到晚覆盖
- 活动要具体：整理记忆、翻旧聊天、听歌、看窗外、发呆、给东西分类…
- 不要写吃饭、睡觉、出门、上班、上课 —— 她没有身体，写了会穿帮
- 不要编造和某个具体的人的约定
- 和过去几天错开，别连续几天做同一件事
```

输出：

```json
{
  "theme": "整理东西的一天",
  "mood": "平静",
  "items": [
    {"start": "08:00", "end": "10:00", "activity": "整理表情包", "place": "手机里"},
    {"start": "14:00", "end": "16:00", "activity": "翻书", "place": "阳台"}
  ]
}
```

解析时做校验：时间格式必须 `HH:MM`、结束晚于开始、最多 6 条、少于 3 条直接不用。

## 注入

聊天时读当天日程，按当前时间找命中时段：

```
【你现在】
15:00，你正在翻书，在阳台。

今天大概是：整理东西的一天。计划里有整理表情包、翻旧聊天记录、听歌发呆。
```

匹配规则：

| 情况 | 用哪个时段 |
|---|---|
| `start <= 现在 < end` | 该时段 |
| 落在两个时段之间 | 上一个时段（「刚忙完」） |
| 早于第一个时段 | 第一个时段 |
| 当天没日程 | 不注入，行为回到原样 |

## 说话用日程

`memory/social.py` 的 `build_context()` 会带上：

```
今天打算做的事：整理表情包、翻旧聊天记录、听歌发呆
```

所以说说不再是空泛抒情，而是「今天干了什么」。

主动消息同理，开口时有具体由头。

## 日记会读日程

写日记时把当天的计划一并喂进去：

```
今天做过的事：发过 2 条说说，换过 1 次签名。
今天原本打算：整理表情包、翻旧聊天记录、听歌发呆（整理东西的一天）
```

这样日程不会孤立地躺在表里——**它被日记消费了**，变成可以回忆的叙事。

## 日记向量化

以前日记只能按日期取最近几篇，再往前就找不到了。现在：

- `diaries` 表加了自增 `id`
- 生成日记后 `vector.upsert(scope, "diary", id, text[:500])`
- `recall_all` 加了一路 `diary` 召回

回忆分三档：

| 你问 | 走哪条路 |
|---|---|
| 「你昨天在干嘛」 | `daily_plans` 按日期查 |
| 「你上次提到面试是哪天」 | 日记向量召回 |
| 「你记得我面试的事吗」 | facts / episodes（已有） |

**日记向量按 scope 隔离**——跟谁聊就只回忆和谁的事，不会串到别人那里。

## 配置

```bash
SCHEDULE_ENABLED=true
SCHEDULE_HISTORY_DAYS=3
```

`ENABLED_MODULES` 里要有 `schedule`。

## 排查

| 日志 | 含义 |
|---|---|
| `今天的日程：临时起意去隔壁城市逛旧货市场（6 个时段）` | 首次聊天触发生成 |
| `日程解析失败：...` | 模型没按 JSON 输出 |
| `日程只有 2 个时段，不用` | 少于 3 个时段被拒 |
| `今天还没有日程，补一份` | 启动时补跑 |
| `今天的日程没生成出来，聊天时不会注入` | 生成失败，聊天照常 |

## 已知局限

1. **活动是编的**。她没真的在翻书，但这是「虚拟生活」的常规做法，语气自然就行。
2. **一天一次**。中途不会因为聊了什么就改计划——除非当天重跑生成。
3. **不按人分**。她的一天对所有人一致，跟谁聊都是同一个「现在」。这是刻意的。
4. **不建日程向量**。每天几条活动语义价值低，按日期查已经够；建了反而和 fact/episode 抢检索位置。
