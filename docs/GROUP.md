# 群聊

## 隔离模型：记录分开，认知留在群内

这是整套设计的地基。

| 内容 | 存哪 | 群聊能看到 | 私聊能看到 |
|---|---|---|---|
| 原始消息 | `group:<群号>` / `private:<QQ>` | 只看本群 | 只看本私聊 |
| 摘要 summaries | 同上 | 只看本群 | 只看本私聊 |
| 事件 episodes | 同上 | 只看本群 | 只看本私聊 |
| 事实 facts | 同上 | 只看本群 | 只看本私聊 |
| 向量 embeddings | 同上 | 只看本群 | 只看本私聊 |
| 群成员 group_members | `group:<群号>` | **只看本群** | 看不到 |
| 人格 traits | `bot:self` | 共享 | 共享 |
| 日记 diaries | `bot:self` | 共享 | 共享 |

**「记住群里的人」是在群内部成立的**：群成员、谁说过什么、群内聊过的事实，全部落在 `group:<群号>` 里。她在群里能说出「张三喜欢猫，李四最近在找工作」，但换到私聊，这些记忆完全不可见。

### 为什么不做跨会话的用户画像

隐私取舍。如果她的 `user:<QQ>` 画像里存着「你女朋友叫小美」，那你在群里出现时它也可能被注入——群友随便一句话就可能套出来。

所以这套设计**只有群内认知**。代价：私聊里认识的你，在群里她不认得，得重新认识。

如果后续要「群里也认得私聊里的你」，需要单独做一层带 visibility 标记的画像（私密事实只能在私聊提）。

## 触发规则：四级优先级

从上往下，命中即决定。

| 顺序 | 条件 | 行为 |
|---|---|---|
| 1 | 消息里有 `at` 段指向机器人 QQ | **必回** |
| 2 | 文本含触发词（默认「大肥鱼」） | **必回** |
| 3 | 处于**活跃期** | **必回** |
| 4 | 其他 | 按 `GROUP_REPLY_CHANCE`（0.2）**概率回** |

第 4 级还要过两道过滤：

- 少于 `GROUP_MIN_CHARS`（4 字）的消息不接
- 距上次群回复不足 `GROUP_REPLY_COOLDOWN`（60 秒）不接

**无论回不回，白名单群的所有消息都会记录。** 这是她能「知道群里发生过什么」的前提。

## 「回了就继续聊」

每次成功回复，写一个时间戳：

```
group_active_until:<群号> = now + GROUP_ACTIVE_MINUTES * 60
```

在这段时间内（默认 5 分钟），群里任何人说话都命中优先级 3，她直接接着聊，不再掷骰子。

每次回复都会刷新计时。沉默超时后自动回到监听模式，重新按 @ / 叫名字 / 概率触发。

这样不会「回一句就消失」，也不会无限缠着。

## 她在群里的身份

- 群里叫她 **大肥鱼**，prompt 里会明确写出来
- **人设里她仍叫周周**。如果你想全局改名，那是改 `persona.md`，跟这个配置无关
- 「当前说话的是谁、是不是主人」由系统按 QQ 号判定，群里自称不算

## 群聊 prompt 长这样

```
你现在在一个 QQ 群里聊天，群里的人都叫你「大肥鱼」。
当前说话的是「张三」（QQ 222），不是你的主人。
群号 1083370981，群里还有别人在看。

你在这个群里还认识这些人：
- 李四

群聊规矩：
- 只接当前说话的人，别把别人的话当成对你说的。
- 你正在跟他们聊着，就接着聊；聊完这阵子再自然停下。
- 不要提你和主人私聊里的事，一个字都别提。
- 不要提你在别的群、别的私聊里说过什么。
- 不确定的就不说，别替别人补充。
- 称呼用群名片，别用私聊里的叫法。
```

## 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `GROUP_ENABLED` | `true` | 总开关。关掉后退回纯私聊策略 |
| `GROUP_WHITELIST` | `1083370981` | 逗号分隔的群号；空=不接任何群 |
| `GROUP_TRIGGER_NAMES` | `大肥鱼` | 命中就必回的名字，逗号分隔 |
| `GROUP_REPLY_CHANCE` | `0.2` | 没触发时插话的概率 |
| `GROUP_REPLY_COOLDOWN` | `60` | 概率回复的最小间隔（秒） |
| `GROUP_ACTIVE_MINUTES` | `5` | 回过话后保持对话的时长（分钟） |
| `GROUP_MIN_CHARS` | `4` | 太短的消息不接 |
| `GROUP_MAX_CONTEXT` | `40` | 群聊回放历史条数 |
| `GROUP_MEMBER_LIMIT` | `15` | prompt 里最多列几个群成员 |

调参：

- 觉得她太吵 → 调小 `GROUP_REPLY_CHANCE`、`GROUP_ACTIVE_MINUTES`
- 觉得她太闷 → 调大 `GROUP_REPLY_CHANCE`，或者把 `GROUP_MIN_CHARS` 调小
- 一句话都不想你还要被回复 → `GROUP_ENABLED=false`

## 调试

**日志关键字**

| 日志 | 含义 |
|---|---|
| `群聊已启用，白名单群：1083370981` | 正常 |
| `群消息 group=xxx 不在白名单，已忽略` | 群号没配，把它加进 `GROUP_WHITELIST` |
| `收到消息（scope=group:1083370981）` | 消息进来了 |
| `已回复 N 段，共 M 字` | 她回了 |
| `群消息 group=... 已记录` | 只记录没回复（概率没中） |

## 已知局限

1. **群聊记录多了会撑大 prompt**。`GROUP_MAX_CONTEXT=40` 是为了多给上下文，但群消息碎，40 条可能上千字。嫌长就调小。
2. **概率回复可能答非所问**。她不知道那句话不是对她说的，全靠 prompt 里的「只接当前说话的人」约束。调低概率是更可靠的解法。
3. **群成员靠说话积累**，不主动拉群列表。刚进群时不认识任何人，聊过才有记录。
4. **跨群不共享**。同一个群友在两个群说话，两套独立记录。
5. **隐私边界是软约束**。「不要提私聊内容」写在 prompt 里，模型理论上可能违反。真要硬隔离，得在检索层就切断——现在的 scope 隔离已经做到了这一点，prompt 只是加强。
