# 人格与成长

## 三层结构

| 层 | 存哪 | 谁改 | 变的频率 |
|---|---|---|---|
| **骨架（canon）** | `src/qqbot/persona/persona.md` | 只有人手动改 | 几乎不变 |
| **成长层（traits）** | 表 `persona_traits` | 系统自动，有证据门槛 | 几天到几周 |
| **状态层（state）** | 表 `self_state` | 情绪机、主动消息 | 每条消息都在变 |

核心约定：**成长层绝不回写 `persona.md`**。

自动改写会越改越乱、没法回退，而且会把「爱用行吧」这种现状固化成人格。所以骨架和成长分开存，长歪了一条 SQL 清空就回到零点。

## 骨架怎么写

参考了三种主流写法（详见 `docs/` 外的调研结论）：

- **Character Card V2** 的 `mes_example`（对话示例比性格描述有效）和 `post_history_instructions`（对抗长对话的角色漂移）
- 火山引擎《角色扮演场景提示词指南》的维度清单，以及「形容词堆砌无效」的对比实验
- 中文陪伴类项目「小焦」模板的**正反例对照**和「不讨好 / 不重复 / 不纠缠」四原则

所以 `persona.md` 的结构是：

```
身份 → 性格（行为化）→ 说话方式（要什么 + 人机味黑名单）
→ 口头禅（带场景）→ 说话示例（正反例）→ 能力 → 边界
→ 抗漂移段 → 关于变化（告诉它成长层存在）
```

两条硬规则：

1. **性格写成行为，不写形容词**。「幽默」模型各有各的理解；「他说我不困，你说你眼睛快粘屏幕上了」才有用。
2. **必须有正反例**。示例里的「烂」写法就是它容易掉进去的坑。

## 成长层怎么工作

```
每 10 轮
  └─ 抽人格信号（style / address / interest / character / lore）
       ├─ 与已有记录做相似度归并（向量优先，退回字符 bigram）
       │     └─ 归并失败会导致同一件事散成多条候选，永远攒不够证据
       ├─ 累加 evidence_count，达到 3 次 → 升级 active
       └─ active 超过 12 条 → 淘汰证据最少的
```

### 五类信号

| kind | 意思 | 例子 |
|---|---|---|
| `style` | 说话习惯 | 「你正在戒掉「行吧」，改说「成」」 |
| `address` | 称呼 | 「你叫他「老板」，他闹着让你叫爸爸，你不从」 |
| `interest` | 兴趣 | 「你对 CS 比赛熟了，能接得上话」 |
| `character` | 性格微调 | 「你变得更会顶嘴，离谱要求直接拒绝」 |
| `lore` | 两人之间的梗 | 「你记着「三年前买黄金就包养你」的空头支票」 |

### 两条关键约束

**① 只抽「变化」，不抽「现状」。**

提示词里写死了这条。否则模型会抽「你爱用「行吧」接话」——一旦升级，就等于把她固定在一个你已经嫌弃的习惯上。

**② 性格类最多 2 条生效。**

其它类型可以长到 12 条，但 `character` 只取证据最多的两条进入 prompt。防止几天之内变成另一个人。

### prompt 长这样

注入在 persona 之后、时间之前：

```
你最近的变化（这是你自己长出来的，已经是你的一部分，自然地用，别当清单念）：
- 你变得更会顶嘴，对方提离谱要求时直接拒绝并反将一军。
- 你开始用「哥」称呼对方，不再顺着叫爸爸或老公。
- 你正在戒掉「行吧」，改说「行」或「行行行」。
```

## 为什么这样做（研究依据）

[AutoPersonas](https://ar5iv.labs.arxiv.org/html/2607.08252)（2026）研究长期人格演化，提出 **self-locking**：人格循环表面在产出新内容，功能上却反复回到同一个吸引子。

它给了四个直接可用的思路：

1. **证据门槛**——新信号要「硬化」成证据才能改状态，否则只是装饰
2. **多时间尺度**——快循环记观察，慢循环决定「重复的弱信号是否构成状态级变化」
3. **当前状态权威要受控**——状态保连续性但不能垄断未来，落到这里是骨架不可变 + 成长独立
4. **变化要有因果链**——信号 → 证据 → 状态 → 行为，否则就是随机漂移

我们砍掉了它的「人格有自己的生活」那部分（不适用一对一陪伴），只留了证据治理。

## 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `GROWTH_ENABLED` | `true` | 总开关，关掉就不抽取也不注入 |
| `GROWTH_EVERY` | `10` | 每多少轮观察一次 |
| `GROWTH_PROMOTE_AFTER` | `3` | 同一变化出现几次才生效 |

调参建议：

- 觉得她变太快 → 把 `GROWTH_PROMOTE_AFTER` 调到 5
- 觉得根本不长 → 调到 2，或者把 `GROWTH_EVERY` 调到 6
- 觉得 prompt 被撑太长 → 改 `memory/growth.py` 里的 `MAX_ACTIVE`

## 已知局限

1. **措辞漂移是真实存在的问题**。模型每次描述同一件事都会换说法，靠向量归并兜底（阈值 `MERGE_THRESHOLD=0.82`）。归并不住的时候会留下相似候选，占用 12 条额度。
2. **一次性玩笑偶尔会被抽成 lore**。比如「拿丫丫自比」，提示词说了不要，模型有时还是给。它只是候选，攒不到 3 次不会生效。
3. **没有时间衰减**。一条 active 只要不被淘汰就一直生效。如果发现她卡在某个旧变化上，手动 `--clear` 或单独删行。
4. **不区分「她真的变了」和「她演了一次」**。目前靠证据次数硬扛。
